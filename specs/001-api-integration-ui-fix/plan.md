# Implementation Plan: CMS API Integration, User ID Fix & Color Update

**Branch**: `001-api-integration-ui-fix` | **Date**: 2026-06-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-api-integration-ui-fix/spec.md`

---

## Summary

Integrate 4 CMS tracking APIs (ping/pageview/conversation/diagnosis) into the AgriApp React Native client using a centralized fire-and-forget service. Fix the hardcoded `USER_ID` in `AIChatScreen.js` and `PestScreen.js` to dynamically use the logged-in user's phone number or a session-scoped guest UUID. Change the app's primary color from agricultural green to `#0066BC` by updating the theme token file.

---

## Technical Context

**Language/Version**: JavaScript (React Native 0.76.9, Expo SDK 52)

**Primary Dependencies**: `@react-navigation/bottom-tabs` (tab focus events), `react-native` AppState API (foreground detection), `@react-native-async-storage/async-storage` (existing auth persistence — not used for new feature)

**Storage**: No new storage. Guest UUID is in-memory (module-level singleton). CMS events are fire-and-forget with no local persistence.

**Testing**: Manual validation per `quickstart.md`. No automated test runner configured in project.

**Target Platform**: Android + iOS (Expo managed workflow)

**Performance Goals**: Ping adds ≤1 network request per 30s; all CMS calls are fire-and-forget and do not block UI thread.

**Constraints**: `EXPO_PUBLIC_` prefix required for all env vars accessed in bundle. No new npm packages.

**Scale/Scope**: 5 files modified, 1 new service file created. Theme change propagates via existing token system.

## Implementation Sequence

### Step 1 — Environment Variables

Update `.env`: rename `APP_SECRET` → `EXPO_PUBLIC_APP_SECRET`, add `EXPO_PUBLIC_CMS_BASE_URL`.

### Step 2 — cmsService.js (new file)

Create `src/services/cmsService.js` with:

- Module-level `SESSION_ID` and `GUEST_SESSION_UUID` (both UUID v4)
- `getEffectiveUserId(user)` helper
- `sendPing(user, currentPage)` — POST /api/ping
- `trackPageview(user, pageName)` — POST /api/pageview
- `trackConversation(user)` — POST /api/conversation
- `trackDiagnosis(user, cropType, result)` — POST /api/diagnosis
- All functions: fire-and-forget (no await at call site)

### Step 3 — Theme Color Update

In `src/theme/index.js`:

- `primary: '#0066BC'`
- `primaryLight: '#3385CC'`
- `primaryDark: '#004A8F'`
- `primaryGradientStart: '#1A7AD4'`
- `primaryGradientEnd: '#0066BC'`
- `success: '#4CAF50'` — unchanged

### Step 4 — AIChatScreen.js User ID Fix

- Import `useAuth` from AuthContext
- Import `getEffectiveUserId`, `trackConversation` from cmsService
- Replace `const USER_ID = 'Trợ lý AI..._user'` with `const { user } = useAuth()` + derive user_id at call time
- Replace all occurrences of `USER_ID` with `getEffectiveUserId(user)`
- Call `trackConversation(user)` on first message send (when starting a new conversation)

### Step 5 — PestScreen.js User ID Fix

- Same pattern as AIChatScreen.js
- Replace hardcoded USER_ID with `getEffectiveUserId(user)`
- Call `trackDiagnosis(user, cropType, diagnosisResult)` after successful AI response

### Step 6 — App.js Ping Heartbeat

- Import `AppState` from react-native
- Import `sendPing` from cmsService
- Add `useEffect` for AppState listener + 30s interval (starts on mount, clears on unmount/background)
- Access `user` from `useAuth()` (already inside `AuthProvider` in App.js)

### Step 7 — AppNavigator.js Pageview

- Import `trackPageview` from cmsService
- In each of the 4 tracked tab screens (or in their route configuration), add `useFocusEffect` / `navigation.addListener('focus')` calling `trackPageview(user, 'home' | 'chat' | 'pest' | 'market')`
